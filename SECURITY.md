# Security Policy

## Supported versions

The latest version on the `main` branch is the primary supported version.

## Reporting a vulnerability

Please do not disclose a suspected security vulnerability in a public GitHub issue.

Use GitHub's **Private Vulnerability Reporting** or **Security Advisories** for the repository when available.

When reporting an issue, include:

- A description of the vulnerability
- Steps to reproduce it
- The affected version or commit
- Any relevant browser, operating system, or deployment details
- A minimal proof of concept when safe to provide

Please do not upload real Kiro conversations, credentials, access tokens, or other private data as part of a report.

## Privacy-sensitive reports

Because this application processes chat exports, treat conversation contents as potentially sensitive. Security reports and bug reports should use sanitized or synthetic examples whenever possible.
